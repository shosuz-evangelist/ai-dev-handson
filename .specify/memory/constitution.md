# Project Constitution

このプロジェクトの規約です。すべての AI ツールがここを参照します（[AGENTS.md](../../AGENTS.md) から 1 行参照）。

## 技術スタック（固定）

- Backend : Java 21 / Spring Boot 3.x
- DB      : PostgreSQL 15+ / Flyway
- Build   : Maven（`backend/mvnw`）
- Test    : JUnit 5 / Mockito / MockMvc

## 命名・API 規約

- REST。エンドポイントは複数形（`/api/customers`、`/api/products`）
- リクエスト / レスポンスは DTO と Entity を分ける
- 入力検証は `@Valid` を使う
- エラーは HTTP の意味に合わせる（重複 409 / 不在 404 / 入力不正 400）

## データの扱い

- スキーマの変更は `backend/src/main/resources/db/migration/` に **新しいマイグレーションを追加**する。既存ファイルは書き換えない
- 顧客の削除は論理削除（`deleted_at` を立てる）。一覧では既定で除外する
- 顧客の `email` は一意
- 更新は PUT で全項目更新

## 逆質問（AI が仕様の抜けを聞く）

仕様が曖昧なまま実装に入らないこと。`/speckit-clarify` で次の観点を確認する。

1. 入力と出力（項目、必須か、型、上限）
2. 一意制約と重複時の振る舞い
3. 存在しない id を指定したときの振る舞い
4. 削除は論理か物理か。削除済みの見え方
5. 認可（未ログインで実行できるか）
6. 性能の目安（応答時間、件数）

## テスト

- 受け入れ基準はテストとして書く。**テストが真**であり、`spec.md` は再生成できる中間生成物
- AI が書いたテストは、観点を人がレビューしてから採用する
- 実装をテストに合わせて直す（テストを実装に合わせて緩めない）

## やらないこと

- 依頼された範囲の外を勝手に直さない。気づいた点は最後に提案として分ける
- 秘密情報をコードやログに書かない
